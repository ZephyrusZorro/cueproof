# Discovery and prior art

Public-source discovery on 10 November 2026. Frequency, severity, and adoption are qualitative estimates. No interviews or operator pilot were conducted.

| Opportunity and user | Trigger, cause, and current approach | Assessment |
| --- | --- | --- |
| Caption revisions for small media teams | Every revised track. Time edits, inserted cues, and renumbering make a line diff noisy. Editors use tools such as Subtitle Edit, browser diff tools, and notes. | High accessibility impact. A local, decision-oriented handoff can be built and tested with ordinary files. |
| Rental condition evidence for tenants | At move-in and move-out. Inventory checklists and photos can become separated. | Significant individual impact, but infrequent use and local process variation. [Camden checklist](https://privaterenters.camden.gov.uk/en/inventory-checklist) |
| School ventilation task follow-up | Recurring checks. Paper logs and checklists require ownership across staff. | Valuable, but school workflow and facilities systems need stakeholder access. [EPA guidance](https://www.epa.gov/iaq-schools/indoor-air-quality-tools-schools-preventive-maintenance-guidance-documents) |
| Near-miss follow-up for small shops | After a near miss. Observations need triage and root-cause follow-up. | High stakes, with organizational trust and sector-specific policy dependencies. [OSHA](https://www.osha.gov/safety-management/hazard-identification) |
| Device reuse custody for refurbishers | Every storage device. Inventory and sanitization records can drift apart. | Useful but relies on correctly authorized and verified sanitization. [NIST](https://csrc.nist.gov/pubs/sp/800/88/r2/final) |
| Oral-history clip indexing for archives | Each interview. Recordings, logs and transcripts take time to reconcile. | Feasible, but finding a narrow workflow with a clear adoption case requires archivist feedback. [Smithsonian](https://siarchives.si.edu/history/how-do-oral-history) |
| Household medical bill reconciliation | Each unclear bill. Separate provider and insurer paperwork makes errors hard to spot. | High potential impact. Sensitive data, inconsistent documents and financial risk constrain a first release. [CFPB](https://www.consumerfinance.gov/ask-cfpb/what-should-i-do-if-i-cant-pay-a-medical-bill-en-2125/) |
| Mutual-aid equipment handover | Each deployment. Resources change owner and location across organizations. | High coordination value. Shared authority, offline sync and incident exercises matter. [USFA](https://www.usfa.fema.gov/a-z/nims/managing-resources/) |
| Food waste measurement for cafés | Daily or weekly. Staff have to record weight, cause and source during service. | Real repetition but accuracy still depends on shift practice. [EPA assessment resources](https://www.epa.gov/sustainable-management-food/food-waste-assessment-and-tracking-tools) |
| Venue visual guides for autistic visitors | Each unfamiliar venue or event. Sensory and route information are scattered. | High usefulness with operator-supplied photos and visitor testing. [National Autistic Society event guidance](https://www.autism.org.uk/advice-and-guidance/topics/leisure/going-out) |
| Volunteer repair intake | Every repair event. A paper ticket can separate the item, volunteer and outcome. | Buildable, but scope would duplicate a tool already delivered in this workspace. [Repair Café](https://www.repaircafe.org/en/) |

Caption revisions ranked ahead of rental evidence, oral-history indexing and refurbisher custody for repeat use, suitability for file-based verification, and low setup cost. The W3C describes the need for speech and meaningful sound in captions. YouTube explicitly asks authors to review automatic output. Neither source establishes demand for Cueproof specifically. [W3C](https://www.w3.org/WAI/media/av/captions/) · [YouTube](https://support.google.com/youtube/answer/6373554?hl=en)

## Competitor and source inspection

| Project | Verified capabilities and approach | Implication |
| --- | --- | --- |
| Subtitle Edit | MIT, active C# desktop project. Its Compare aligner uses unique text/timing anchors and dynamic programming with a large-input fallback. The UI supports comparison, editing and a separate rule-based error list. Source has targeted comparison tests and documented format, sync and waveform workflows. | The strongest functional alternative. Cueproof's differentiator is an opinionated review queue with saved dispositions, explicit split/merge groups, optional local playback and a portable handoff. An open issue describes an overlapping-cue merge workflow concern, rather than a verified defect in all versions. |
| Aegisub | Active C++ desktop editor with timeline, audio waveform, rich ASS styling and SRT import. Source maps supported HTML-like SRT styling tags. Recent releases include UI refinements and a security fix for referenced Automation scripts. | A strong authoring tool. A browser tool can keep revision review focused and render imported text as data. No Aegisub source or assets are redistributed. |
| CaptionCheck | MIT local JavaScript app, CLI and library. README and checked-in tests cover batch reading-speed, line length, timing and glossary checks. | Local checks are already available. Human decisions and media context are the product boundary here. |
| SubtitleWise | Hosted comparison tool documents cross-format comparison and timing differences. Its implementation and runtime measurements were unavailable for source review. | Browser diffs already exist. Cueproof needs the persistent disposition and handoff workflow to earn its place. |
| Maris Stella Caption Quality Checker | Documents local SRT/WebVTT checks and an equivalent CLI. | Confirms that a local advisory lint report alone is insufficient differentiation. |

## Reuse decisions

- Use [jsdiff](https://github.com/kpdecker/jsdiff) for a bounded, whitespace-aware inline word diff. Its Myers-derived diff implementation and tests are established. Use a current release after the published patch-processing advisory and avoid its patch APIs. BSD-3-Clause notice travels with the project and build.
- Evaluate [W3C WebVTT parser](https://github.com/w3c/webvtt.js) and [js-vtt](https://github.com/codeit-ninja/js-vtt). The desk requires source block line numbers, strict reporting on ambiguous input, raw styling/settings evidence, and one import contract across formats. Use a small original block scanner for that scope and native media playback. Follow [WebVTT syntax](https://www.w3.org/TR/webvtt1/) and the [Library of Congress SRT format description](https://www.loc.gov/preservation/digital/formats/fdd/fdd000569.shtml). This parser is scoped to UTF-8 review inputs and is not a general conformance validator.
- Original work comprises the bounded alignment, split/merge grouping, review model, storage, and UI. Native file, media, and IndexedDB APIs avoid a server and keep confidential tracks on the device.
